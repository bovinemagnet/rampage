= Rampage
:author: Paul Snow
:version: 0.0.0

Rampage is a configuration-driven Gatling load testing framework. YAML files describe the environment, run, and scenarios; a thin Java engine resolves them into Gatling protocols, scenarios, feeders, and injection profiles.

== Why Rampage

* Three orthogonal YAML files — environment, run, scenario — so the same scenarios run unchanged across local, CI, and perf environments.
* Native GraphQL request shape with externalised query files and SQL-backed feeders.
* Open and closed workload models, including smoke, baseline, ramp-and-hold, soak, spike, and stress profiles.
* Secret-aware validation that fails fast when required credentials are missing.
* Run metadata, dry-run summaries, and sanitised configuration snapshots written alongside the Gatling HTML report.
* CI quality gate: `summariseRun` parses Gatling reports, emits structured JSON and Markdown summaries, and compares against a stored baseline to detect performance regressions on every pull request.
* Scenario scaffolding from browser captures (`importHar`) and OpenAPI 3.x specifications (`importOpenApi`), reducing the time to instrument a new service.

== Architecture at a glance

YAML configuration is parsed, placeholders expanded, and all three layers validated; only then does the factory layer compose the Gatling simulation. No traffic is generated until every layer passes.
